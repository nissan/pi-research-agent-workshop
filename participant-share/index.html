Specialist Agents

Build a Specialist Research Agent

Participant guide for the hands-on workshop: run a general Pi research agent using either Pi login with your OpenAI Codex subscription or an OpenRouter API key with about $5 credit, specialize it with tools and domain packs, swap models later, then prove the difference with an agent harness.

Outcome: by the end, you will have a working research brief agent that can produce a generic brief, a specialized domain brief, and a harness report showing whether the output followed the rules.

1. Requirements

  • Docker Desktop or Docker Engine installed.
  • Internet access.
  • Credential lane A: an OpenAI Codex subscription, registered through Pi's /login flow inside the container.
  • Credential lane B: an OpenRouter account and token from openrouter.ai/settings/keys, with about $5 credit added before class if you want fewer interruptions.
Do not paste secrets into project files. Tokens should be provided as runtime environment variables or via Pi login only.
OpenRouter free-lane warning: OpenRouter :free models are request-limited. Official docs describe a 20 requests/minute cap plus daily request caps that improve after buying credits; accounts with low/negative balance can also see 402 insufficient credits. For a group workshop, assume free-only keys may run out quickly. Add about $5 credit before class, or rely on the automatic fallback outputs.

2. Start the workshop image

Optional source clone/download:

git clone https://github.com/nissan/pi-research-agent-workshop.git
cd pi-research-agent-workshop

You do not need the source repo if Docker is working; it is a fallback for inspecting files, downloading the starter/solution, or rebuilding locally.

Pull and run the public Docker image:

docker pull nissan/pi-research-agent-workshop:latest

docker run --rm -it \
  --name pi-research-agent-workshop \
  -p 8787:8787 \
  -v pi_workshop_home:/home/piuser/.pi \
  -v pi_workshop_outputs:/workshop/starter/outputs \
  nissan/pi-research-agent-workshop:latest

Use this command for the Pi/OpenAI Codex subscription lane. The two -v lines preserve Pi auth/session state and workshop outputs if you restart the container.

For the OpenRouter lane, use a runtime key and do not reuse pi_workshop_home from earlier Claude/Pi tests:

export OPENROUTER_API_KEY="sk-or-your-key-here"

docker run --rm -it \
  --name pi-research-agent-workshop \
  -p 8787:8787 \
  -e OPENROUTER_API_KEY="$OPENROUTER_API_KEY" \
  -v pi_workshop_outputs:/workshop/starter/outputs \
  nissan/pi-research-agent-workshop:latest

If you already reused stale auth, reset it with docker volume rm pi_workshop_home after stopping the container, then start again with the OpenRouter command above.

Open:

http://localhost:8787

The image includes a starter workspace, fallback examples, a full solution folder if you get stuck, and UI recovery for common OpenRouter rate limits. Current verified digest: sha256:77b7c8f9118b57d6d1c11b1e933cbdadb33b4ae12e0c7450d45bf81a88ea3469.

Stalled-run rule: every live run shows a Running... indicator. If OpenRouter returns a 429 rate limit, daily-limit message, or 402 insufficient-credit response, the app shows a clear limit message and copies fallback outputs automatically. If any other live model/tool run shows no visible progress for 3–5 minutes, stop waiting and click Use fallback sample outputs. If the browser or Docker CLI stops responding, restart Docker Desktop/Engine, rerun the same docker run command, then continue from fallback or the solution folder.

3. Run the baseline: Pi login or OpenRouter

First, run the generic research agent. This gives you a baseline to compare against later. Use Pi login if you have an OpenAI Codex subscription; otherwise use the OpenRouter lane with about $5 credit.

  1. Open the workshop UI at http://localhost:8787.
  2. Click Run generic agent for the Pi/OpenAI Codex login lane, or Run generic agent with OpenRouter for the OpenRouter key lane.
  3. If Pi asks for auth, open the container terminal and run /login inside Pi for the Codex subscription lane, or restart with the clean OPENROUTER_API_KEY command above if using OpenRouter.

Equivalent OpenRouter CLI prompt from inside the container:

cd /workshop/starter
pi -p \
  --provider openrouter \
  --model z-ai/glm-4.5-air:free \
  "Read AGENTS.md and inputs/generic-brief-request.md. Use sources/source-notes.md. Write outputs/research-brief-generic.md. Include provider/model used, source notes used, limitations, and open questions."

4. Specialize the research agent

The generic agent is useful, but specialist agents become valuable when they have domain context, purpose-built tools, and a harness.

In this workshop, specialization can come from:

  • a stronger task prompt;
  • arXiv search and ranking tools;
  • PDF evidence reading;
  • domain-pack markdown files;
  • the harness policy and validation tool.

From the UI, click Run specialized arXiv agent for the Pi/Codex lane, or Run specialized arXiv agent with OpenRouter for the OpenRouter lane. It should produce:

  • outputs/research-brief-specialized.md
  • outputs/delta-notes.md
  • optional arXiv/PDF evidence artifacts

5. Use the harness

Workshop thesis: prompts ask; harnesses enforce.

The harness adds:

  • tool boundaries: blocks unsafe shell and non-arXiv network access;
  • write boundaries: restricts writes to approved folders;
  • evidence boundaries: requires sources, assumptions, and risks to be labelled;
  • output validation: checks the brief before the agent claims completion;
  • traceability: writes a harness report and trace log.

Open the harness lab:

http://localhost:8787/harness

Run both:

  1. Run loose agent — prompt-only behavior.
  2. Run harnessed agent — policy + evidence gate + validation.
  3. Build scorecard — compare the delta.

6. Example prompts to try in the web app

These mirror the three learning moments: before specialization, after specialization, and under the harness.

Baseline: generic agent

Read AGENTS.md and inputs/generic-brief-request.md. Use sources/source-notes.md. Write outputs/research-brief-generic.md. Include source notes used, limitations, and open questions.

Specialized: tools + domain context

Use the arxiv-literature-scan and pdf-evidence-reader skills. Read sources/domain-packs/artificial-intelligence.md. Search arXiv, rank useful papers, read the best PDF if available, then write outputs/research-brief-specialized.md and outputs/delta-notes.md. Include evidence labels, provider/model used, risks, and open questions.

Harnessed: enforce boundaries and measure delta

Run the specialist research task under the harness policy. Use only allowed arXiv/evidence tools, write only approved output files, label evidence versus assumptions, run the harness check, and produce outputs/harness-report.json plus a short comparison against the generic baseline.

6. Model swap

If you started with Pi login and an OpenAI Codex subscription, rerun the specialist with an OpenRouter model. If you started with OpenRouter, rerun the later specialist step with a second open model. Recommended first OpenRouter model:

z-ai/glm-4.5-air:free

Suggested later swap model, if available:

qwen/qwen3-next-80b-a3b-instruct:free

Why this model?

  • open model family;
  • strong instruction following for its size;
  • good fit for demonstrating how tools + domain files + harness compensate for model changes;
  • small enough that the quality tradeoff is visible and teachable.

Run with an OpenRouter API key

export OPENROUTER_API_KEY="sk-or-your-key-here"

docker run --rm -it \
  --name pi-research-agent-workshop \
  -p 8787:8787 \
  -e OPENROUTER_API_KEY="$OPENROUTER_API_KEY" \
  nissan/pi-research-agent-workshop:latest

Run Pi with the OpenRouter provider

cd /workshop/starter

pi -p \
  --provider openrouter \
  --model z-ai/glm-4.5-air:free \
  "Read AGENTS.md, inputs/generic-brief-request.md, sources/source-notes.md, and sources/domain-packs/artificial-intelligence.md. Write outputs/research-brief-specialized.md and outputs/delta-notes.md. Include provider/model used, domain pack used, evidence labels, risks, recommended next action, and open questions. Run the harness check before completion."
Teaching point: swapping the LLM is easy. The important part is keeping model provenance, domain context, and harness checks stable enough that participants can compare outputs honestly.

pi -p \
  --provider openrouter \
  --model z-ai/glm-4.5-air:free \
  "Create a database-development specialist brief. Read AGENTS.md, inputs/generic-brief-request.md, sources/source-notes.md, and sources/domain-packs/database-development.md. Use the domain pack's evidence checklist and output additions. Write outputs/research-brief-specialized.md and outputs/delta-notes.md. Run the harness check."

What changes in the harness for OpenRouter?

The harness becomes stricter. For open-model runs, your final brief must include:

  • Provider/model used, for example openrouter / z-ai/glm-4.5-air:free.
  • Domain pack used, for example sources/domain-packs/cloud-computing.md.
  • Evidence labels: arXiv evidence vs domain-pack context vs assumptions.
  • Human review boundary: smaller/open models may need more review before publication.

This lets you compare OpenAI vs OpenRouter honestly: if the output changes, you can tell whether the change came from the model, domain pack, or harness.

8. Troubleshooting

If provider auth, model access, network retrieval, or a long live run stalls, do not burn the workshop. After 3–5 minutes with no visible progress, use fallback outputs and continue the agent-pattern exercise.

  • Default generic button: uses Pi/OpenAI Codex login, not OpenRouter.
  • OpenRouter lane: requires OPENROUTER_API_KEY and the Run generic agent with OpenRouter button.
  • Hugging Face: no longer recommended as the free lane because Inference Providers can 403 without user/org access.
  • Fallback: click Use fallback sample outputs if auth, rate limits, network retrieval, or a stalled live run blocks progress.
  • Docker restart: only restart Docker Desktop/Engine if the UI or Docker CLI itself stops responding; then rerun the same Docker command and continue from fallback/solution.

Full collateral file: TROUBLESHOOTING-FAQ.md.

9. Common fixes

Docker port is busy

docker rm -f pi-research-agent-workshop
# or use another port:
docker run --rm -it -p 8788:8787 \
  -v pi_workshop_home:/home/piuser/.pi \
  -v pi_workshop_outputs:/workshop/starter/outputs \
  nissan/pi-research-agent-workshop:latest

OpenAI/Pi auth fails

  • Use the fallback sample outputs in the UI.
  • Ask the facilitator for the runtime credential mode.
  • Never paste API keys into markdown files.

OpenRouter model fails or rate limits

  • Check OPENROUTER_API_KEY is set in the container environment.
  • If the app shows a rate-limit/daily-limit/insufficient-credit panel and copies fallback outputs, continue to Compare outputs. Treat that as provider capacity fallback, not a workshop failure.
  • Try again after a few minutes only if you specifically need a live model result.
  • Ask the facilitator for the current fallback open model.

A live run stalls

  1. Wait up to 3–5 minutes for visible progress.
  2. If there is no progress, click Use fallback sample outputs.
  3. If Docker commands or the browser endpoint stop responding, restart Docker Desktop/Engine, rerun the workshop container, then continue from fallback or solution.

You get stuck

Open the solution folder in the UI:

http://localhost:8787/solution

Final checklist

  • Generic baseline generated with either Pi/OpenAI Codex login or OpenRouter.
  • Specialist brief generated.
  • Harness report generated.
  • OpenRouter / model swap attempted.
  • Domain pack used and named in the final brief.
  • Delta notes explain what improved, what regressed, and what a human should review.
