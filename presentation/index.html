Agents and Agent Harnesses

From using AI tools to packaging reliable specialist capabilities.

Run time: 20 minutes. Then participants build, specialize, harness, and measure a Pi research agent.
0-3 minutes

What makes an agent different from a chatbot?

  • A chatbot answers in the moment.
  • An agent works inside a system: files, tools, instructions, state, and feedback.
  • A useful agent leaves artifacts another person or system can inspect.
Agent anatomy

Agent = model + role + context + tools + checks

Role

What job is this agent hired to do?

Tools

What actions can it safely take?

Context

What files, examples, and memory guide it?

Checks

How do we know the result is usable?

OpenClaw pattern

Production agent teams use specialized roles

  • Orchestrator: chooses the route and owns final synthesis.
  • Researcher: gathers context and evidence.
  • Builder: edits code or artifacts.
  • QA: tests behavior and finds failure modes.
  • Planner: turns goals into constraints and acceptance criteria.
3-7 minutes

Specialization is more than a better prompt

  • Prompt: the instruction.
  • Tool: the action surface.
  • Skill: reusable procedure.
  • Domain pack: local expertise and examples.
  • Harness: boundaries, telemetry, and validation.
7-12 minutes

Prompts ask. Harnesses enforce.

Prompt-only agent

  • Can sound correct.
  • May skip evidence boundaries.
  • May use tools inconsistently.
  • Produces prose, not proof.

Harnessed specialist

  • Tool policy constrains actions.
  • Evidence gate validates output.
  • Trace artifacts show what happened.
  • Harness report becomes a trust artifact.
Harness components

A harness wraps the model with operating rules

  • Allowed tools and blocked actions.
  • Evidence requirements and source boundaries.
  • Output schema and quality checklist.
  • Telemetry: traces, logs, provenance, and reports.
  • Recovery path when providers or tools fail.
12-16 minutes

Measuring improvement needs a baseline

Generic0 / 5

Loose prompt, weak evidence, no enforceable checks.

→
Harnessed5 / 5

Policy, evidence, provenance, trace, validation.

The exact number matters less than the visible delta. Participants should see what changed and why.
Workshop lab

The hands-on loop

  1. Run a generic research brief agent.
  2. Add tools, domain context, and specialist instructions.
  3. Run loose agent vs harnessed agent.
  4. Build the scorecard.
  5. Inspect harness-report.json and compare outputs.
Telemetry

What telemetry teaches us

  • Which tool paths were actually used?
  • Where did the agent skip evidence or overclaim?
  • Did model swap change quality or just wording?
  • Which failure should become the next harness rule?
Trust artifact

The report is part of the product

  • Inputs used.
  • Tools called.
  • Evidence checked.
  • Validation result.
  • Known limitations and review boundaries.
Reddi Agent Protocol bridge

A specialist listing should expose its harness

  • Input contract.
  • Allowed tools.
  • Evidence policy.
  • Validation report.
  • Trace or audit artifact.
  • Price and usage assumptions.
16-20 minutes

What participants will build now

  • A local Pi research agent in Docker.
  • A generic baseline brief.
  • A specialist arXiv/domain-pack brief.
  • A harnessed run with scorecard and report.
  • A clearer sense of what could be sold or reused.
